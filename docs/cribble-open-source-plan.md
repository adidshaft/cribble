> **Purpose:** a concrete, ordered checklist for turning Cribble from "public repo" into a
> properly licensed, well-organized, sustainable open-source project that coexists with the
> paid app. Nothing here is executed yet — this is the runbook for when we pick it up.

---

## 0. Why this is needed (one-paragraph context)

The repo is public on GitHub but has **no `LICENSE` file**. Legally, "public on GitHub" is not
"open source" — with no license, default copyright applies and **all rights are reserved**, so
no one may legally fork, modify, or redistribute. Until a license lands, the README's
"open source" framing is aspirational. Cribble is also a **paid app** (App Store IAP / DMG with
Local AI unlock), so the license choice must protect the business while inviting contribution.

---

## 1. Decisions to make first (blockers)

These gate everything else. Make them explicitly before touching files.

### 1.1 Licensing model

| Option | Open part | Paid part | Notes |
|--------|-----------|-----------|-------|
| **Open core** *(recommended)* | Reader, Markdown engine, diff engine, Intelligence framework, provider protocol | Cloud sync / premium models / team features / convenience binary | Matches existing IAP reality |
| **Source-available** (BSL / Elastic v2 / FSL) | Everything readable & buildable | Commercial/competing use restricted; converts to OSS after N years | Strongest moat, weaker "true OSS" cred |
| **Permissive (MIT/Apache-2.0) whole app** | Everything | Nothing (rely on hosted/convenience) | Maximal community, weakest moat |
| **Copyleft (GPL/AGPL)** | Everything | — | ❌ Avoid — incompatible with App Store + paid binary |

**Recommendation:** **Open core, Apache-2.0** for framework/engine modules (Apache over MIT for
the explicit patent grant, which matters with LLM/codegen). Keep the app shell either Apache-2.0
(monetize convenience + cloud) or under a source-available license if a moat is required.
**Decision owner:** maintainer. **Output:** a one-line written decision recorded in `GOVERNANCE.md`.

### 1.2 Contributor agreement

Choose **DCO** (lightweight `Signed-off-by`, recommended for a solo project) vs **CLA** (heavier,
enables relicensing later). Recommendation: **DCO** now; revisit if a foundation/company forms.

### 1.3 CoC enforcement contact

A real email/address for Code of Conduct + security reports.

## 2. Repository hygiene files (in priority order)

Create at repo root unless noted. Each line is one deliverable.

1. **`LICENSE`** — per §1.1. *Blocker for all "open source" claims.*
2. **`CONTRIBUTING.md`** — build from source (`./script/build_and_run.sh`), run tests
   (`swift test`), branch/PR conventions, DCO sign-off instructions, and the non-negotiable
   product principles (reader-only, preview-before-mutation, local-first). State realistic
   response expectations for a solo maintainer.
3. **`CODE_OF_CONDUCT.md`** — Contributor Covenant v2.1 + contact from §1.3.
4. **`SECURITY.md`** — disclosure address, supported versions, "Cribble reads your code and runs
   models locally — here's our data posture" statement. High importance for this app class.
5. **`GOVERNANCE.md`** — decision process (even if "BDFL: maintainer"), scope (what Cribble will
   and won't become), and an explicit **hand-off / archival plan** (industry data: ~70% of OSS is
   one maintainer — say what happens if they step away).
6. **`ROADMAP.md`** — link `cribble-intelligence-plan.md §15` phasing + this plan; keep honest.
7. **`ARCHITECTURE.md`** — hand-written first pass; later regenerated by Cribble Intelligence
   itself as a dogfooding showcase.
8. **`.github/ISSUE_TEMPLATE/`** + **`PULL_REQUEST_TEMPLATE.md`** — bug / feature / provider
   templates.
9. **Labels** — `good first issue`, `provider`, `intelligence`, `reader`, `diff`, `docs`.
10. **`CHANGELOG.md`** — already exists; keep maintaining.

## 3. Modularization (so contribution is actually possible)

Split the SwiftPM package (`Package.swift` already has room to grow) into libraries with clean
seams. Target structure:

| Module | Contents | Reusable standalone? | Contribution magnet? |
|--------|----------|----------------------|----------------------|
| `CribbleMarkdown` | Markdown parse/render, rich fenced blocks, Mermaid | ✅ | medium |
| `CribbleDiff` | Unified-diff parse / preview / apply | ✅ | medium |
| `CribbleIntelligence` | Engine, job queue, artifact store, **`IntelligenceProvider` protocol** | partial | high |
| `CribbleProviders` | `MLXIntelligenceProvider` + `OpenAICompatibleProvider` | ✅ | **highest** |
| `Cribble` (app) | macOS shell composing the above | — | low |

**Strategic principle:** make the **provider protocol** and the **artifact/job model** the
stable, documented *public API*. Community PRs flow into providers and job types; the app shell
and business logic stay maintainer-owned. This is how open core stays healthy.

**Steps:**
1. Audit current `Sources/Cribble/{Stores,Services,Models,Views,Support}` for natural seams.
2. Extract `CribbleDiff` first (cleanest boundary, genuinely standalone, low risk).
3. Extract `CribbleMarkdown` second.
4. Land `CribbleIntelligence` + `CribbleProviders` as the Intelligence feature matures (depends
   on the intelligence branch).
5. Document each module's public surface; add per-module README.

---

## 4. Optional: headless CLI on-ramp

A `cribble-intel` CLI that runs the Intelligence engine over a folder and emits artifacts
(à la CodeBoarding). Benefits: testable in CI, usable by non-Mac contributors, second discovery
on-ramp. **Gate behind demand** — don't build speculatively. Listed here so it's not forgotten.

---

## 5. Sustainability & community

- **Funding:** keep IAP / paid binary as the primary engine (research is unanimous goodwill alone
  doesn't sustain maintainers). Add **GitHub Sponsors** (and optionally Open Collective) for
  self-builders — low effort, real signal.
- **Expectation-setting:** advertise *transparency and forkability*, not guaranteed PR SLAs.
- **Discoverability:** SwiftPM metadata, GitHub topics, one-command build, self-generated
  `ARCHITECTURE.md` as the headline demo.
- **Security-as-marketing:** "local-first, on-device, nothing leaves your machine, every AI claim
  is source-cited" is both the UX and the open-source trust pitch — make it loud.

---

## 6. Execution sequence (do in this order)

1. **Decide §1** (license model, DCO/CLA, contacts) — record in writing.
2. **Add `LICENSE`** — unblocks the "open source" claim.
3. Add `CONTRIBUTING`, `CODE_OF_CONDUCT`, `SECURITY`, issue/PR templates, labels.
4. Extract `CribbleDiff` + `CribbleMarkdown` modules; document public surfaces.
5. Add `GOVERNANCE.md` (with hand-off plan), `ROADMAP.md`, first `ARCHITECTURE.md`.
6. Open **GitHub Sponsors**.
7. Land `CribbleIntelligence` + `CribbleProviders` modules (after intelligence branch matures);
   document the **provider protocol** as the public contribution API.
8. *(Optional)* ship `cribble-intel` CLI.
9. **Only after step 2**, update README/site to claim open source accurately and announce.
